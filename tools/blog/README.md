# Блог: як з'являється стаття

Статті блогу не редагуються руками у `blog/*.html` — ці файли складає
`tools/blog/build.py`. Джерел у нього два, і вони не рівні за призначенням.

**1. Написані руками** — модуль `art_*.py` з одним словником `ART`, підключений
у `articles.py`. Тут доступна вся розмітка блоків: врізка викладача (`expert`),
питання-відповідь усередині тексту (`qa`), контекстне посилання на посадкову
(`courselink`), таблиці, списки, HowTo. Так пишуться статті, у які вкладаються.

**2. З конвеєра мережі** — файл JSON у `content/`. Сусідній проєкт
(`my_computer_new`) має конвеєр статей: хмарний агент за розкладом пише статтю,
кладе її в чергу, а GitHub Actions публікує. FluentFox під'єднаний до нього
04.09.2026 і отримує статтю раз на тиждень. Файл приїжджає в `content/`,
складається разом з рештою і лишається в репозиторії назавжди — з нього стаття
перескладається, якщо зміниться шаблон.

Формат JSON — той самий, що й у всієї мережі (`slug`, `title`, `title_ru`,
`excerpt`, `excerpt_ru`, `content`, `content_ru`, `category`, `category_ru`,
`coverEmoji`, `author`), плюс необов'язкові `published` і `faq`. Розбирає його
`queue.py`; там же білий список тегів, які дозволено в `content`. Це навмисно
простіший формат, ніж `art_*.py`: конвеєр читає один формат для всіх сайтів, а
кожен зайвий різновид розмітки — ще один спосіб зламати нічний прогон.

## Чому складання чіпає ще чотири файли

Стаття, на яку ніхто не посилається, для пошуку не існує. Тому `build.py` після
складання сторінок кличе `site_index.apply()`, і той оновлює:

* `blog/index.html` — картки (`const articles`), `<noscript>`-перелік і розмітку
  блогу (`blogPost`, `ItemList`);
* `sitemap.xml` — блок статей блогу з hreflang;
* `llms.txt` — розділ «Статті блогу», який читають ІІ-краулери;
* `blog/articles.json` — машиночитаний перелік; його читає не сайт, а знімок
  конвеєра в сусідньому репозиторії (у мережі те саме віддає `/api/articles`,
  а статичному сайту нізвідки його взяти).

Джерело правди для всіх чотирьох — `listing.json`: перелік карток у тому
порядку, в якому вони на сторінці. Нова стаття стає першою, наявна оновлюється
на місці. Поля `excerpt`, `emoji`, `catKey`, `llmsTitle`, `llmsDesc` — це
окремі тексти, коротші за ті, що на сторінці; у статей, написаних руками, вони
живуть тільки тут, і складання їх не затирає.

## Перед пушем

```
python tools/blog/build.py
python tools/audit/run.py
```

Аудит перевіряє те, що ламається саме в такому конвеєрі: посилання на статтю,
якої немає (сирота навпаки), закоротке `description`, маркери ІІ у тексті,
розбіжності між мовними версіями. У прогоні конвеєра він стоїть перед пушем —
не пройшов, стаття лишається в черзі й нічого не публікується.
