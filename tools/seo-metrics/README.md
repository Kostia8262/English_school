# Показатели продвижения

Сбор цифр из Search Console и Google Analytics в своё хранилище плюс печать
отчёта. Перенесено из сети «Мой компьютер»
(`my_computer_new/tools/seo-metrics`), где то же самое кормит вкладку «SEO» в
админке.

**Зачем своё хранилище, а не смотреть в интерфейсе Google.** Окно Search
Console скользящее: доменный ресурс копит статистику только с момента
подтверждения, и то, что видно сегодня, через год недоступно. Не сложив срез к
себе, сравнивать следующий сентябрь будет не с чем. Плюс отчёт в терминале
отвечает на вопрос «как наши успехи» за одну команду, а не за десять кликов по
двум интерфейсам.

**Чего здесь нет по сравнению с сетевой версией.** `collect-logs.js` — логи
доступа живут на сервере, а сайт на Hostinger, где их так не почитать.
`crawl-pages.js` — обход своих страниц у нас делает `tools/audit/run.py`.
Колонки `site` нет ни в одной таблице: сайт один, вместо неё фильтр по хосту на
входе (сервисный аккаунт видит и ресурсы соседней сети, и без фильтра её строки
утекли бы сюда).

## Запуск

```
node tools/seo-metrics/collect-gsc.js --check     # только проверить доступ
node tools/seo-metrics/collect-gsc.js             # добрать хвост в 14 дней и окно запросов
node tools/seo-metrics/collect-gsc.js --backfill  # первый заход: вся доступная история

node tools/seo-metrics/collect-ga.js --check
node tools/seo-metrics/collect-ga.js              # добрать хвост в 7 дней и окно страниц
node tools/seo-metrics/collect-ga.js --backfill

node tools/seo-metrics/report.js                  # окно 28 дней против предыдущих 28
node tools/seo-metrics/report.js --days 7
```

Порядок первого запуска: оба `--backfill`, затем `report.js`. Дальше — оба
сборщика без флагов раз в неделю; повторный сбор того же периода безопасен,
записи заменяются по ключу.

Нужен Node 22+: хранилище на встроенном `node:sqlite`, зависимостей у скриптов
нет ни одной.

## Доступ

Ключ сервисного аккаунта — в `GSC_KEY_FILE` или флагом `--key`, по умолчанию
`~/secrets/gsc.json`. **Ключа в репозитории нет и быть не должно** — репозиторий
публичный. Аккаунт тот же, что у сети «Мой компьютер» (на её VPS лежит в
`/root/secrets/gsc.json`), область прав у каждого сборщика своя: Search Console
читает `webmasters.readonly`, Analytics — `analytics.readonly`.

Чтобы аккаунт увидел наши данные, его почту надо добавить:

- в Search Console — пользователем ресурса `fluent-fox.site` (для показов и
  позиций хватает «Ограниченного»);
- в GA4 — читателем ресурса `545484974`. **Это уже сделано**: ресурс с
  21.09.2026 собирается сетевым коллектором, там же видно 54 сессии за 28 дней.

Идентификатор ресурса GA4 — не секрет, поэтому лежит прямо в `collect-ga.js`
(переопределяется через `GA_PROPERTY`). Он не то же самое, что счётчик
`G-K60LSESFTV` на страницах: Data API просит числовой идентификатор.

Хранилище — `tools/seo-metrics/data/seo.db`, в `.gitignore`. Переопределяется
через `SEO_DB_FILE`.

## Что нужно знать про эти данные, иначе отчёт соврёт убедительно

- **Позиция уже усреднена по показам внутри строки.** Складывать позиции при
  объединении строк нельзя: среднее от средних даст строке с одним показом тот
  же вес, что строке с тысячей. Только взвешенно по показам —
  `weightedPosition` в `store.js`, и так же считает `report.js`.
- **Search Console отстаёт на два-три дня** и ещё несколько дней дозаполняет
  задним числом. Поэтому сборщик перезабирает хвост в 14 дней, а не вчерашний
  день. У GA то же самое, хвост 7 дней.
- **Предел ответа GSC — 25 000 строк на страницу.** Чем больше измерений в
  запросе, тем быстрее упрёшься и тем незаметнее срежется хвост из редких
  запросов — ровно тех, ради которых всё и затевалось. Поэтому запросы узкие:
  отдельно «дата + страница», отдельно «запрос + страница» окном, без даты.
- **История GA глубже, чем у GSC** — с момента установки счётчика против
  скользящего окна ресурса. Это единственный источник, по которому можно
  сравнить год с годом.
- **Свои визиты отсеиваются на входе** (`NOT_A_SITE`), а не в отчёте: цифра,
  которую надо мысленно уменьшать, рано или поздно уедет в отчёт как есть.
- **`userEngagementDuration` — сумма секунд, а не среднее.** Среднее GA считает
  по сессиям, и к странице оно не подходит: делим на просмотры сами.
- **Русская версия отдаётся по тому же адресу** (`?lang=ru`, внутренний rewrite
  в `.htaccess`), поэтому в разбивке по страницам обе языковые версии сливаются
  в одну строку. Отделить их по этим данным нельзя — это свойство схемы, а не
  потеря при сборе.

`tools/` исключена из rsync-деплоя, так что ни скрипты, ни база на прод не
попадают.
